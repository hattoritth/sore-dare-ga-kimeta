# F5「それ、誰が決めた？」最適化報告

- 作成日: 2026-11-01（日本時間）
- 作業基準: ユーザー提供の `sore-dare-ga-kimeta-main(1).zip` （ZIP内の全55エントリ）
- 対象: F5 AIゼミ展示ゲームの一人モード、共有モード、Local API、Worker、オフラインHTML
- 非対象: GitHubへのpush/merge、SitesやCloudflareへの本番デプロイ、会社D1の設定/書換、会場機材の操作

## 要約

既存の2.5D都市描画と4人のキャラクター、ソロ4判断・共有7ラウンドを維持し、警告/終了ルール、介入、情報の秘匿、共有APIの整合、モバイル表示、リリース資材の再現性を改善した。

## 実装した主な変更

1. **しきい値を共通化** — `WARN_THRESHOLD=30`, `END_THRESHOLD=10` を表3項目（繁栄・便利さ・街の魅力）、裏3項目（信頼・公正・持続性）のすべてへ厳密な `<` 条件で適用。終了時は対応する街の重大トラブルを提示。
2. **警告イベントと介入** — 警告中は住民の声を表示。次ラウンドで人の判断が過半数なら、警告対象指標へ追加回復 `round(8 × 人の票比率)` を加算。一人モードでは人の選択が対象となる。強制的に判断回数を増やさない。
3. **判断の足跡** — 結末画面に展開式の判断履歴を追加。個人名を他参加者へ公開せず、人・AI・票数と結果を確認可能。
4. **街の事件表現** — 洪水、住民の反対運動、交通網停止、財政破綻、住民離脱、分断に対応した結末文を生成し、街の状態表示と描画トーンも変える。
5. **画面の処理量を抑制** — 不要な毎250msの全面描画を削減し、Canvas描画をページ非表示時に抑制、画面サイズ・モーション削減設定に応じて描画間隔を調整。複数建設が同時に反映される際のキャッシュ再作成を1回に統合。
6. **共有APIの防御** — ローカルサーバーをWorkerと同じラウンド必須・同一オリジン・二重投票・急速な変更抑制・参加上限に統一。QRの遷移先も同一ホストのトップページに限定。Workerの例外応答を一般化し、静的成果物へCSP/Referrer-Policyを追加。
7. **単体HTMLの同期** — `site/scripts/build-standalone.mjs` を追加し、既存の `site/public` からオフラインHTMLを生成。ファイル環境の単独プレイ遷移を修正し、動作しない共有モードは非表示とした。
8. **テスト改善** — `npm test` の前にWorker・単体HTMLを自動ビルドするように変更し、ルールのソース一致、6指標の境界値、介入、情報秘匿、API安全性、生成物を検証。

## 未検証・リスク

- **本番接続:** Cloudflare/Sitesへのデプロイ、社内D1バインディング、HTTPS、5人以上のネットワーク同時負荷、Wi-Fi再接続・遅延については対象外。URL公開は承認と適切な資格情報の管理が前提。
- **既存ゲーム状態:** 開発中の旧ゲームデータが永続化されている場合、途中セッションのしきい値解釈は更新前後で異なる。リリース時は管理者判断でセッション切替・リハーサルを実施する。データ削除はしていない。
- **コンテンツ:** AI委任はシナリオルールであり、実LLM推論ではない。表と裏の6指標、4判断/7ラウンドは現行ソースに合わせた構成。F5チームから提示された5つの街パラメーター案への全面変更は合意未確認のため保留。
- **参加者の名前:** 名前はサーバー内に保存されるが、参加者の名前を公開結果へ掲載する仕様は導入していない。明示同意と展示のプライバシー方針を確認する必要がある。
- **古いエントリーポイント:** `site/worker/index.js` はスターター画面であり、ゲームのWorkerではない。公開時のエントリーポイント指定に注意。

## 手元での再現手順

```sh
cd site
npm test
node scripts/validate-artifact.mjs
node server.mjs
```

- 一人モード: `http://localhost:4173/?mode=solo`
- モード選択: `http://localhost:4173/`
- 共有モード: `http://localhost:4173/?mode=group`
- 展示モニター: `http://localhost:4173/?view=display`
- オフライン: `standalone/それ、誰が決めた？_街が動く版.html` を開き「ひとりで遊ぶ」

**推奨する次の受け入れ条件:** 展示用iPad（1024×768横）・iPhone（390×844縦）・モニター（1920×1080）で、人→AIの交互選択、全AI選択、警告後の人間介入、複数人投票、再接続、QR参加、全画面表示を確認。実装・検証済みでも、展示会場の本番設定への反映は別途承認が必要。
