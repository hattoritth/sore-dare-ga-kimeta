# F5 次期UX改修：共有票の対比・AIワンタップ・街の可視性

## 採用方針
- 共有票: 各ラウンドについてサーバーが確定した人/AIの票数・採用/保留と、「このタブでサーバーから確認できた自分の票」を区別する。個人票はページ内メモリに保持するのみ。名前・Cookie・個人票をD1やローカルストレージへ追加保存しない。再読み込みで以前の票が消えたら「このタブでの記録なし」。途中参加で知らない回は推測しない。街が切り替われば記録を初期化する。
- AIワンタップ: 本編のAIボタンは「AIに任せる」のみを主体にし、押した時点で意思表示する。最初の診療所でも追加の確認はせず、駅前のAI提案を記録して即時に1票を投じる。街の変化と住民の声は表示後に自動で次へ。人の選択は従来どおり場所・理由・対応または検討方針を扱う。チュートリアルのAI選択も、自動で本編/参加受付へ進む。
- 街の見やすさ: 通常の会話パネルと街の変化カードをキャンバスの上に重ねない。横長画面は左右独立、縦長画面は街を上・会話を下に置く。クリック可能領域を保持し、街の変化時もキャンバスを拡大しない。大きな都市情景を見渡せる構成にする。

## 制約と検証
- GitHub PR #8 55c4a86 を基点とした新しい開発ブランチ。旧リリースの公開サイトには変更を加えない。
- ゲームの4/7判断、採点、6指標・6種類の結末、共有投票タイマー23秒、D1、API、DB binding、QRを変更しない。
- 現行Sites用パッケージにはmigration SQLを含めない。
- 親側のMac通常環境で93/93件の自動テストが成功。HTML要素欠落をブラウザー実検証で発見・修正し、追加の回帰テストを設置した。
- 390×844、820×1180、1024×768、1920×1080のChromiumで街と会話の重なりが0・横スクロールなし。ソロAIの1タップ、住民反応を経て自動進行、人の選択に伴う追加入力の維持を確認。
- Chromiumのローカル模擬共有ゲームで3人が投票（人1対AI2）、人に投票した本人の画面に「自分：人／街：AI」が表示されることを確認。本番D1や実機Safariの確認ではない。
- 新機能はGitHubに保存・レビューしてからリリース判断。Sitesデプロイ・main mergeは実行しない。
