# PR #22: 初見の共有モード結末案内（v21候補）

## 根因

公開v20で匿名の来場者が共有モードへ入った時点で街が `reveal` だった。アプリはこのフェーズで参加フォームを隠して結果を見せるが、未参加者が今は参加できない理由や参加可能になる条件を案内していなかった。これは通常の結果表示フェーズで、DB障害ではない。

## UX変更

共有モード・未参加者・`reveal` の組み合わせに限り、結果パネル上部へ「今は結果を表示中です。次の街から参加できます。」と、任意の「ひとりで遊ぶ →」導線を表示する。ソロ導線は既存のソロモードへ移動し、join/vote等のAPIを呼ばない。街の結果と進行表示はそのまま維持し、他フェーズ・参加者・ソロには案内を表示しない。街のティッカーは結末の既存文言を維持し、参加状況の案内を重複させない。次の街の開始時刻は示さない。

- **Macの通常環境で `npm test` 163/163件成功、0失敗。** Codex隔離環境では既存のHTTPサーバー統合テスト2件のみloopback待受 `listen EPERM` で実行不能だったため、ホストで再テストして解消を確認。アプリの回帰ではなかった。

## 対象範囲と限界

変更対象はUI、テスト、説明文、生成されるソロ単体HTML。Worker API、DBスキーマ、migration、bindingは変更しない。公開v20で確認された導線不足に対するローカル修正候補であり、この差分をv21として公開・デプロイした事実はない。Chrome/PuppeteerのUI検証は実施済みだが、本番へのv21デプロイ・本番DB参加テストは別の工程。物理iPhone/iPad、実D1同時参加、実公開環境でのv21表示は未検証。
