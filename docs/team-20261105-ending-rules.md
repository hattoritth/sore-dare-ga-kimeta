# 結末の表示と判定ルール（チームレビュー用）

この文書は v25 のゲーム判定を変えず、結末表示のレビュー対象と、現行実装から確認できる事実を分けて記録する。判定・しきい値・スコア式の変更は含まない。

## 現行実装で確認できる事実

- 6つの指標は繁栄、便利さ、街の魅力、信頼、公正、持続性。ゲーム中は算術平均を四捨五入した「街の幸福度」を表示し、個別値は結末後に表示する。
- 警告は指標が **30未満**、BAD結末は指標が **10未満**。いずれも境界値を含まない。警告は結末ではなく、警告のまま街が続く状態として扱う。
- BADの原因は `state.ending.metric` と、実際に発生した事象の `state.incident` が示す。表示文言と会見の背景はこの状態を使い、別の事件を作らない。
- NORMALは大きな事故が発生しなかった結末。解消していない判断のトレードオフと、今後も確かめる責任を結果カードに明記する。
- 判断保留は WARNING と別状態。保留された議題と確認事項を説明し、実際に起きていない災害や抗議を描かない。
- 人が決める案には、声を聞きやすい一方で話し合いの偏りや実行の遅れが起きうる。AI案には、予測や運用で利便性・繁栄を高める一方で、前提の偏りや説明責任、長期の備えが残る場合がある。どちらも一律に善悪とは扱わない。
- AIボタンは人の案と同じ1票の選択肢。6指標の新設、重み変更、スコア式変更はない。

## 結末と代表経路

| 種別 | 現行の条件・代表例 | 表示方針 |
| --- | --- | --- |
| BAD | 6指標のいずれかが10未満。原因指標と実際の事象は `ending.metric` / `incident` を参照 | 事象を具体的に表示。6指標を会見後の結果で公開 |
| WARNING | 10未満はないが、いずれかが30未満 | 事故を捏造せず、警告された課題と必要な対応を説明 |
| 判断保留 | 全議題が投票なし、または全議題が保留 | 未決の議題と確認事項を説明。WARNINGとは別の図柄 |
| NORMAL | 上記に該当せず、TRUE条件を満たさない | 大きな事故がないこと、未解消のトレードオフと責任を明記 |
| TRUE（暫定） | 警告なし、規定の選択履歴、6指標すべて40以上など | 役割分担を描写。条件はチームレビューで確定するまで暫定 |

現行の一人用 TRUE 経路は、選択種別 `human,human,human,ai`、対応する具体案の末尾 `listen,listen,listen,ai`、警告なし、6指標すべて40以上。共有モードでは1・3・6・7番目を人、4番目をAI、2番目または5番目をAIにし、すべての具体案と履歴条件を満たしたうえで6指標が40以上である必要がある。これらは現在のエンジン実装の記録であり、チームが承認した完成ルートとはみなさない。

## TRUE条件のレビュー待ち（PROVISIONAL）

`TRUE_METRIC_FLOOR = 40` と特殊な役割ルートは暫定仕様。レビュー承認までは式・数値・ルートを変更しない。

受け入れ条件：

1. TRUEが特定の正解ボタン列やAI使用回数の報酬に見えず、人とAIの異なる貢献、実際の結果、確認責任を表すとチームが承認する。
2. 40の下限を含む各条件について、条件を一つずつ外した場合にTRUEにならない境界ケースがテストされている。
3. BAD / WARNING / 判断保留 / NORMAL / TRUEの優先順と、全ルートの説明文・会見画像・カード表示をチームが受け入れる。
4. 変更を決めた場合は、別の承認済みタスクでエンジン・テスト・説明を同時に更新する。

## 今回の画面順

結末状態に入ると、個別6指標と結果カードの前に、全画面の記者会見を表示する。会見は質問・回答・締めの順に進み、「会見を省略して結果へ」でも同じ結果画面へ進める。締めの後は結果カードと保存操作を表示する。結果画面から会見を再生すると古い字幕と指標DOMを消し、再生中の遅延コールバックも無効化する。

BAD6種、NORMAL、TRUE、WARNING、判断保留にはそれぞれ街の建物と会見台を描くインラインSVGを用いる。外部画像・フォント・CDNを読み込まない。
