# TRUE END の役割バランス（2026-11-03）

## 判定方針

TRUE END は指標の高さだけでは獲得できない。結末時に確定した判断の履歴を評価し、話題に合った責任分担と実際のフォローアップ、街の健全さがそろった場合だけ付与する。進行中の `publicState` には結末種別も非公開指標名も出さず、既存の `game.outcome` は通常・TRUEとも `survived` のまま保つ。`endingFor` 相当の `ending.kind` で `true` と `stable` を区別する。

既存の6指標、各選択の影響、警告30未満・崩壊10未満の境界、6つの危機結末、投票集計は変更しない。TRUE の追加条件として全6指標40以上を要求するため、警告がないだけより厳しい余裕を持たせている。

## ソロ

ソロ4判断の唯一のTRUE役割列は、診療所=人、公園=人、海辺=人、電力=AI（H-H-H-A）。診療所は駅前・郊外どちらでもよい。人が選ぶ場合、理由は利用者数ではなく「通院が難しい人への届きやすさ」である `access` を選び、さらに評価確認・通院支援・計画見直しのいずれかを実際に適用する必要がある。場所は地区ごとの事情に応じて選べるため固定しない。

この分担は、住民のアクセス、公園の緑、高潮への備えを人が担い、需要予測に基づく電力運用はAIに任せつつ、人が結果への責任を持つという物語上の区分に対応する。人だけ・AIだけ、誤った担当、根拠だけで実行後の対応がない場合はTRUEにならない。

## 共有プレイ

7判断のうち、診療所・海辺の防災・中央公園・学校の将来準備は人、電力の需要分析はAIが担当する必要がある。企業誘致・交通最適化の少なくとも1つではAIの分析力を活用する。企業と交通の両方をAIが担うルートも、社会的な影響に問題がなければ受け入れる。集計で同数または無投票になった議題は、案が実施されていないためTRUE条件から除外する。

この条件は人またはAIの一方だけで全て決める経路を排除し、特定の正解列を7ラウンド全てに強制しない。結果の正しさは投票列だけでなく、全6指標40以上でも確認する。

## 全経路の列挙結果

現行 `engine.js` の決定ロジックを変更せず、各ラウンドで人またはAIの単独選択を行う全経路を実行した。

- ソロ16経路（人が診療所を選ぶ経路はアクセス理由と「評価を調べ直す」の実行後対応を付与）: TRUE 1、通常 stable 10、warning 3、collapse 2。
- 共有128経路: TRUE 2（1.56%）、通常 stable 53、warning 24、collapse 49。
- 共有TRUEのビット列（bit 0 が第1ラウンド、1=AI、0=人）: `24, 26`。人/AI全同一の経路はいずれもTRUEではない。
- 共有TRUEの全指標は40以上。32/32の同数投票や無投票経路はTRUEではない。

列挙結果は現行スコアと閾値に基づくローカル実行であり、プレイヤー調査や実機・本番Sitesでの到達率を示すものではない。ソロは診療所の場所2種、アクセス理由、実行後対応3種の組み合わせごとの分布ではなく、16通りの役割列を検証した。

## 実装と制約

分類は結末表示時に既存の確定履歴・実際に建設された施設・ソロ詳細・診療所の実行記録・最終指標から純粋に計算する。D1/API/保存スキーマには新しいフィールドを加えない。完全な履歴やソロ詳細がない手動モック状態からTRUEは出ない。`game.outcome` は既存互換のため `survived` のままで、画面・結果カードでは `ending.kind` を使って TRUE / NORMAL / WARNING / BAD を表示する。
