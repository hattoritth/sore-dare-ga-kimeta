# 2026-11-04 — Sites R0（UIのみ）バックアップ代替策の承認記録

## 決定
ユーザーはv17〜v19で繰り返し発生した公開停止を把握し、過去バックアップの利用・DB差分不変・公開前後確認による「今後のUIのみの更新に適用する運用方針」を提案された後、**「任せるので公開して」**と指示した。これは**v19の公開承認**と、R0/UI-onlyに限定する**新規フルバックアップ要件の代替策のリスク受容**として扱う。毎回同じ制約だけで再停止せず、守るべき証跡が揃えば公式Sitesで公開する。

## 適用境界
- 適用：v19および将来**ユーザーが公開を別途依頼した**R0/UI-only更新。自動公開・無承認公開は認めない。
- 必須：既存D1の**完全な過去バックアップと復元検証の実証**、同じSite/DB binding、Git差分でDBに影響するWorker/engine/DDL/migration/manifestに変更なし、公開前後のD1両テーブル行数と取得できるversion等の照合、対象SHAと公開権限の確認。取得可能なときは最新フルバックアップを優先。
- 代替不可：R1/R2、未知のDB影響、過去バックアップ未確認、対象違い、破壊的な変更の証拠、サイトIDや公開対象SHAの不一致。実際のデプロイで異常があれば書込みを止める。
- リスク受容：公開直前のD1完全コピーがなく、バックアップ取得後の投票・参加者状態等を失う可能性、本番ライブDDL全文未取得、Sites内部の自動DB操作が未確認。行数/versionだけでデータ一致・完全復元を証明したと主張しない。旧Sites版に戻してもD1は自動復元されない。
- 禁止：追加のGoogleログイン要求、D1初期化、手動migration、新規Site作成、main merge、バックアップ本体のGitHubへのアップロード。
