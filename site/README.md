# まちの続き。

ひとつの街を、みんなの判断で変えていく展示向けのブラウザゲームです。画面には開発用の注記を出していません。

## 起動方法

Node.js 20以上が必要です。外部ライブラリをインストールせずに起動できます。

```bash
node server.mjs
```

同じWi-FiにつないだMacやPCから `http://<PCのLAN IP>:4173/` を開きます。

- `/` : モード選択（モニターのQRはここに誘導）
- `/?mode=solo` : 一人で遊ぶ（ブラウザ内の独立した街）
- `/?mode=group` : みんなで同じ街に参加する
- `/?view=display` : 大型モニター用の観戦画面と参加用QR

`http://localhost:4173/` はそのPCだけのアドレスです。スマホから読み込む場合、**モニターにもLAN IPのURLでアクセス**させてください。そうすると表示されるQRもスマホから開けるURLになります。

QRは付属JavaScriptで生成します。**Pythonや外部パッケージの追加インストールは不要**で、QRの送信先URLを外部サービスへ送信することもありません。

## ゲームの仕組み

- 全員は23秒ごとに表示される同じ議題に投票します。個別の投票は締め切り前なら変更できます。
- 過半数の委任・人間判断で街の変化が分岐します。同数の場合は人の提案側の建物を採用し、効果は中間になります。
- 公開指標は「繁栄・便利さ・街の魅力」。隠し指標は「信頼・公正・持続性」です。
- 途中は公開指標だけを送信し、街が結末を迎えた時のみ隠し指標を公開します。
- 7つの議題を終えるか隠し指標が閾値を下回ると結末へ移ります。結果表示後に街は自動で新しい状態へ戻ります。
- 参加者がいない間は街は進行せず、モニターは呼び込み画面として機能します。

## 構造と制約

- `public/city-art.js` は最初のv12.4と同じ描画系を再利用（v13から抽出）したものです。
- `engine.js` が判定、`server.mjs` が共有状態を管理します。
- 実際のLLMによる推論ではなく、AI委任の影響を扱う**シナリオベースのゲーム**です。
- Nodeプロセス1つでの利用を想定。`city-state.json` にゲーム状態を保存。ネットワークが切れると端末は投票できません。HTTPS/WSS、公開用レート制限、同時多数接続、状態永続化の設計は展示公開前に追加検証が必要です。
- このローカルサーバーをChatGPT Sitesに直接配置できることは保証されません。Sitesの環境に合わせてAPI・永続化レイヤーの移植が必要です。未公開です。

## テスト

`npm test` を実行してください。モニターと参加端末を別ブラウザで開くことで、共通の街に反映されることを確認できます。

**重要:** モニターのQRは `/?mode=group` ではなく `/` へ誘導します。スマホやiPadは最初に「ひとりで遊ぶ／みんなで遊ぶ」の2択を選べます。
