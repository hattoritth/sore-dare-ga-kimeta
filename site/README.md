# まちの続き。

ひとつの街を、みんなの判断で変えていく展示向けのブラウザゲームです。画面には開発用の注記を出していません。

## 起動方法

外部ライブラリをインストールせずに起動できます。検証にはNode.js v24.18.0を使用しました。自動テストは内蔵の `node:sqlite` を使用します。

```bash
node server.mjs
```

同じWi-FiにつないだMacやPCから `http://<PCのLAN IP>:4173/` を開きます。

- `/` : 導入とモード選択
- `/?mode=solo` : 一人で遊ぶ（ブラウザ内の独立した街）
- `/?mode=group` : みんなで同じ街に参加する
- `/?view=display` : 大型モニター用の観戦画面と参加用QR

各画面のQRは既存の公式サイト `https://machi-no-tsuzuki-20261031.tthkpba.chatgpt.site/` を示します。ローカルプレビューのアドレスには依存しません。QR SVGは付属JavaScriptでローカル生成され、外部QRサービスへ送信しません。

**Pythonや外部パッケージの追加インストールは不要**です。

## ゲームの仕組み

- 参加者が最初の1人になってもタイマーは始まりません。接続中の参加者全員が「準備OK」にしてから「みんなで始める」を押すと、最初の判断の23秒が同時に与えられます。90秒間接続が途切れた参加者は準備確認から外れます。途中参加者は進行中の議題では待機し、次の議題から同じ23秒で参加します。その後は23秒ごとに同じ議題へ投票し、締め切り前なら変更できます。
- 有効票が0件なら同票とは扱わず、その議題を判断保留にします。街の指標・施設は変えずに次の議題へ進み、結果履歴にも「投票なし」と記録します。
- 各議題に4つの行動案があります。票は選択肢IDごとに数え、最多票の行動を実施します。最多票が同数の場合は計画を保留します。無投票とは理由を区別します。
- 6つの指標「繁栄・便利さ・街の魅力・信頼・公正・持続性」は、ロビーとゲーム中はすべて非公開です。画面とAPIに出すのは6指標の算術平均を四捨五入した「街の幸福度」だけです。
- ゲーム中のAPIは幸福度だけを返します。個別指標は結末後に6つすべて公開し、レーダーと結果カードに使います。警告は個別指標名や件数を示さない共通の住民の声で表します。
- 7つの議題を終えるか、表・裏いずれかの指標が10未満になると結末へ移ります。30未満で街の異変が現れ、次の行動によって兆候への対策を試みます。結果表示後に街は自動で新しい状態へ戻ります。
- 参加者がいない間は街は進行せず、モニターは呼び込み画面として機能します。

## 構造と制約

- `public/city-art.js` は最初のv12.4と同じ描画系を再利用（v13から抽出）したものです。
- `engine.js` が判定、`server.mjs` が共有状態を管理します。
- 実際のLLMによる推論ではなく、AI委任の影響を扱う**シナリオベースのゲーム**です。
- Nodeプロセス1つでの利用を想定。`city-state.json` にゲーム状態を保存。ネットワークが切れると端末は投票できません。HTTPS/WSS、公開用レート制限、同時多数接続、状態永続化の設計は展示公開前に追加検証が必要です。
- このローカルサーバーをChatGPT Sitesに直接配置できることは保証されません。Sitesの環境に合わせてAPI・永続化レイヤーの移植が必要です。未公開です。

## テスト

`npm test` を実行してください。Workerのビルドと単体HTMLの再生成も自動で実行されます。モニターと参加端末を別ブラウザで開くことで、共通の街に反映されることを確認できます。

各画面のQRは公式サイトのルートを開きます。トップページからは導入とモード選択を体験できます。

## 2026-11-01時点の既存ルール

- 一人モードは4つの重要判断、共有モードは7つの議題です。どちらも警告しきい値30未満・終了しきい値10未満です。
- 警告の次の議題では、行動に応じて警告対象への追加効果を適用します。
- 警告中も個別指標名・値・警告件数をクライアントへ送りません。
- 人間判断の介入は「対策を試みた回数」、警告中の指標が30以上に戻った「警告回復」と、終了しきい値未満になったはずの指標を実際に10以上へ戻した「危機回避」を分けて記録します。
- AIは診療所の需要対応、駅前の公平な投資配分、電力需要の平準化で一部の指標を改善します。人間の話し合いにも時間や代表性の偏りによるコストがあります。
- 結末画面では原因に応じたトラブル説明と、各ラウンドの判断履歴を閲覧できます。履歴に個別参加者の名前は公開しません。
- `standalone/` のHTMLをファイルとして開く場合、共有モードは表示されません。QRはオフラインでも公式サイトへの案内として表示されます。共有プレイにはサーバーまたはWorkerが必要です。

## 2026-11-04 v23の行動選択と幸福度

- 4つのソロ議題と7つの共有議題に、それぞれ固有の日本語で書かれた4行動を用意しています。3つは人が実行する具体的な行動、1つは「AIに任せる」行動です。選択後に場所や方針を追加で選ぶ画面はありません。
- 各行動は施設と6指標へ固有の効果を持ちます。共有は各IDの最多票で実施し、同票・無投票なら変更しません。Workerは現在の議題に登録されたIDだけを受け付けます。既存の `human` / `ai` 投票値は対応する既定行動として読み込めます。
- D1 JSONに `optionVotes` を保存します。テーブルやマイグレーションは増やしません。履歴には勝ったID、実施効果、匿名の選択ID列、各選択肢の票数を保存し、結果画面でのみ表示します。
- 6指標の平均を四捨五入した0–100の「街の幸福度」をゲーム中に表示します。ゲーム中・待機中のAPI、履歴、警告、選択肢、アクセシビリティ文言には個別指標値を含めません。全6値は結末後に公開します。
- 常設QRは既存公式サイトのルートを指します。 `site/src/qr.mjs` からSVGをローカル生成し、オフラインHTMLにはdata URIとして埋め込みます。カメラ権限や外部QRサービスは使いません。
- `npm run qa:happiness` はローカルのモック状態だけで Puppeteer の画面確認を行います。実Sitesと本番D1には接続しません。
- この作業ではローカルのコードと単体HTMLのみを更新・検証します。実Sitesのプレビューや実D1への変更は行っていません。

## Stage 4の結末と再現手順

- 結末は、重大トラブル（いずれか10未満）、課題を残す継続（いずれか10〜29）、比較的安定した継続（すべて30以上）、全議題保留の4種類です。無投票だけの場合は「誰も決めなかった街」、同票を含む全保留は「決めきれなかった街」と説明します。共有は50秒後に新しい街へ戻ります。
- 警告を残す結末ではニュース、街の点検表示、責任履歴も課題継続と一致させます。浸水では道路の冠水、水面、雨、通行止めを表示し、他の重大原因にも交通停止/休業/人通り減少/説明要求を描画します。
- 経路分析: `node scripts/path-analysis.cjs <出力JSONパス>`（site内で実行）。ソロ16・共有128・2人投票集約2,187を出力します。2人投票集約は全員人間/全員AI/同数票の3^7通りで、個別の投票順序や入退室時刻の全組合せではありません。
- 引継ぎZIPの展開直後は、任意の作業ディレクトリから `node <展開先>/evidence/path-analysis.cjs` を実行できます。candidate/ と evidence/ は隣り合う構成です。ローカル作業階層が異なる場合は、第一引数にcandidateディレクトリを指定します。
